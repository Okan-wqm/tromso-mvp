# Languages

The console is available in **English** (`en`, the source language), **Norwegian Bokmål** (`nb`) and
**Turkish** (`tr`). English text in the code and templates is the msgid; the other languages are
translations of it kept in `locale/<language>/LC_MESSAGES/django.po`.

## How a request gets its language

1. A signed-in person who has chosen a language gets it, on every device (`core.language`).
2. Otherwise the cookie `django_language` set by the language switcher.
3. Otherwise the browser's `Accept-Language` (Django's `LocaleMiddleware`).
4. Otherwise English.

The switcher is the EN / TR / NB segment in the user menu and in the corner of the sign-in pages. It
posts to `/language/` (`core.views.set_language`, Django's own `set_language` plus one line): the
choice goes into the cookie (one year) and, when someone is signed in, onto their `Profile`
(`core/models.py`). The sign-in pages have no person yet, so they only set the cookie; once someone
has signed in, their saved language wins over the cookie.

The language lives on a small `Profile` row (one per person, created when they first choose) because
the user model is Django's own and swapping it later would rewrite every table that points at it. The
platform admin can also set it for a person on the user form, which is what makes an invitation arrive
in the new person's language. Emails are written in the recipient's saved language when there is one
and otherwise in the language of the request (`core.forms.PasswordResetForm.send_mail`).

## Numbers and dates

Decimal quantities (areas, coordinates, volumes) are typed and shown the way the language writes them:
the form fields are text inputs with `localized_fields`, so Norwegian and Turkish read and show a
decimal comma (`60,3913`) and a dot is accepted too. Tables group digits with `floatformat:"-2g"`
(`50,000.50`, `50.000,50`, `50 000,50` with a no-break space). `USE_THOUSAND_SEPARATOR` is off, so an
identifier such as the lokalitetsnummer is never shown as `12.345`. Dates use Django's format of the
language (`02 Kasım 2026 13:05`, `2. november 2026 13:05`); English keeps the look the console always
had (`2 Nov 2026, 13:05`) through `config/formats/en/formats.py`. Templates ask for
`DATE_FORMAT` / `DATETIME_FORMAT` instead of spelling a format.

## The activity log is English at rest

Rows never hold translated text. A row stores the English msgid of every field label, the record type
and every enumerated value (a choice such as "Under maintenance", yes/no); the page runs them through
the catalog when it shows them (`AuditLog.shown_type`, `AuditLog.shown_changes`), in the language of
whoever reads. The action ("Created") is stored as its key.

- An enumerated value is stored as `{"msgid": "Under maintenance"}` (`core.audit.message`), and only
  those are translated: a person's own text is stored as written, so a site called "Pond" is not shown
  as the Turkish word for the pond type.
- Every snapshot is built inside `audit.source_language()`, so it comes out in English whatever
  language the person who made the change uses. `Resource.recorded()` does this for every tab;
  anything that writes a log row by hand (`core.crud.RowList.save`, `core.softdelete.execute`) wraps
  itself.
- Field labels are the form labels, which are the model fields' `verbose_name` in sentence case, one
  msgid each. Putting the label on the model is what keeps the form, the admin and the log in step.
- Some summaries are composed text and stay in English in the log: a role's permissions ("Sites:
  read"), a site's contacts ("Kari (Vet, primary)"), the systems a piece of equipment serves ("RAS 1
  (R1): primary, circulation, criticality 4"), a feeder's calibrations ("3.00 mm Starter: 25.00 g per
  shot, silo 250.00 kg"), what a feed suits ("Atlantic salmon (SAL): Smolt, 50–150 g") and a multiple
  choice among the specifications ("Temperature, pH"). The role
  list page translates the permissions because it builds the text at display time.
- Several choices of one field (what a supplier supplies) are stored as a list of
  `{"msgid": ...}` values and shown translated, joined with commas (`core.audit`,
  `AuditLog.shown_changes`).
- A piece of equipment's specifications are logged one per line under their own label (a msgid, like
  a field label), a choice as `{"msgid": ...}`, a number with its unit. The type's name is a catalogue
  msgid too, so the log shows it translated.
- The equipment type catalogue (`farm/equipment_types.py`) is data whose texts (type names, field
  labels, options, placeholders) are msgids, marked with `gettext_noop` where they are written and
  translated when shown. Product and standard names (WiFi, Modbus, HDPE, PVC, pH) are not marked.
- Rows written before this change keep plain English values and show them unchanged.

## Adding a string

1. Write it in English where it is shown, marked: `gettext_lazy as _` for things defined at import
   time (models, forms, menus, `Resource.name`), `gettext` or `ngettext` in views, `{% trans %}` and
   `{% blocktrans %}` in templates. A counted message uses `ngettext` / `{% blocktrans count %}` with
   both forms. Put a `# Translators:` comment (`{# Translators: ... #}` in a template) before a
   message whose placeholders need explaining.
2. Do not build a sentence from parts that other languages order or inflect differently. A noun such as
   a tab's name goes into the sentence as a named placeholder; write the sentence so that the noun is in
   the middle (it is lower case) or, where it starts the sentence, is passed capitalised (`%(name)s`
   in the flash messages, see `core.crud.flash`).
3. `manage.py update_catalogs` adds the new msgid, untranslated, to every `.po` file. Translate it
   there (no empty `msgstr`, no `fuzzy` flag), then `manage.py compile_catalogs`.
4. Run the tests. `core/test_catalogs.py` fails when a msgid is missing or obsolete, when a
   translation is empty, fuzzy, or loses a placeholder or a tag, and, for every tab (`Resource`), when
   a name, label, help text, choice or constraint message is plain text instead of translatable text.

The text of a tab that a person never reads (URLs, `data-` keys, CSS classes, time zone identifiers) is
not translated. Developer messages (system check, management command help) are English.

The database viewer (Administration › Database) shows the database as it is: table, column and type
names, the constraint definitions and the first sentence of a model's docstring (the description of
a table) are the developer's English and stay as they are; its own headings, buttons and notes, the
descriptions configured in `config/database.py` and the kinds of constraint ("Primary key") are
translated.

The browser code has no text of its own (`core/test_catalogs.py` checks that). A text it shows is a
`data-` attribute rendered by a template: `data-label-collapse` / `data-label-expand` on the menu
button, `data-label-show` / `data-label-hide` on a password field's button, `data-forbidden` on the
dialog. `frontend/dom.ts` reads them with `label()`.

## Building the catalogs

GNU gettext (`xgettext`, `msgfmt`) is not needed and not used. Babel (`requirements.txt`) does what
`makemessages` and `compilemessages` do, through two commands:

```
.venv\Scripts\python.exe manage.py update_catalogs     # code and templates -> locale/*/LC_MESSAGES/django.po
.venv\Scripts\python.exe manage.py compile_catalogs    # .po -> .mo, which Django loads
```

The `.mo` files are built and not committed (`.gitignore`), like `static/js`: a fresh checkout runs
`compile_catalogs` once in its setup, and so does the test run (`core/test_catalogs.py`,
`core/test_languages.py`). If a `.mo` is missing or older than its `.po`, the server prints a system
check warning (`core.W002`) instead of silently showing English.

Extraction reads Python with Babel and templates through Django's own `templatize`, as
`makemessages` does (`core/catalogs.py`). The `.po` files are written sorted and without file
locations, so a change to the code shows in them only where a msgid or a translator's note changed.

## Adding a language

1. Add it to `LANGUAGES` in `config/settings.py` (code and its own name, e.g. `('sv', 'Svenska')`).
   Django must ship a catalog for the code (`django/conf/locale/<code>`): its plural rule is copied
   from there.
2. `manage.py update_catalogs` creates `locale/<code>/LC_MESSAGES/django.po` with every msgid.
3. Translate it, `manage.py compile_catalogs`, and add the language to the glossary below.
4. Add a place for its date format only if Django's own is not what you want (`config/formats`).

Sentence shapes used with a tab's noun (`%(name)s`, `%(plural)s`): Turkish and Norwegian put the
noun where their grammar wants it, e.g. "Add site" is `Yeni saha` and `Legg til lokalitet`, "Delete
site" is `Sil: saha` and `Slett lokalitet`, "Save site" is `Kaydet: saha`. The Turkish nouns avoid a
leading `i`, which Python's `capitalize` would turn into `I` instead of `İ`.
