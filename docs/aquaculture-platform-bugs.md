# Bugs found in the aquaculture platform while porting the farm module

Porting the farm module tab by tab means reading its source closely. This document lists what was
found wrong, so it can be fixed in the platform and so the prototype does not repeat it. It grows
with every tab that is ported.

**Source read:** `aquaculture_platform`, branch `snowball-test`, commit `352aa2a8`
(`apps/farm-service`, `web/modules/farm-module`). Paths below are relative to those two folders.

**How reliable each entry is.** Findings come from reading the source. Those marked **✔** were
re-read by hand at the cited lines; the others are as reported by the analysis of the file and
should be confirmed at the cited place before fixing. Line numbers can drift with the branch.

**Severity:** **High** wrong or lost data, or a behaviour the user cannot work around;
**Medium** wrong in some cases, or a trap for later changes; **Low** inconsistency or polish.

**"In the prototype"** says how it is avoided here: by a database constraint, a shared mechanism
in `core/`, or by not porting the feature (satellite monitoring is deliberately left out).

## Patterns that repeat across tabs

These are the root causes behind many of the single entries below. Fixing them once, where they
live, closes the whole class.

| Pattern | Where it shows | Root-cause fix |
|---|---|---|
| **A cleared field cannot be saved.** The forms send `value \|\| undefined`, and the API reads `undefined` as "no change". | Equipment: every optional field and the parent (EQ-02). Systems: department, parent system, description (SYS-01). Departments: notes (DEP-03). Tanks: system, description, sensor (TNK-16). Species: local name, family, official code, notes and more (SPC-09). Suppliers: every optional field (SUP-07). | Send `null` for a cleared optional field, and let the API treat `null` as "clear" and absent as "unchanged". One helper for every form. |
| **Rules that live only in the service code.** The database accepts what the service would refuse. | Name/code uniqueness, one primary contact, department/site match. | Put the rule in the database (unique index with a `WHERE`, check constraint, composite FK) and keep the service check only to give a readable message. |
| **Unique indexes that are not partial** while the services only check live rows. | Sites, departments, systems, species (SPC-12): a deleted record's code can never be reused, and the clash surfaces as a database error. | Make the unique index partial (`WHERE "isDeleted" = false`), or decide that codes are never reused and say so in the message. |
| **Input limits longer than the column.** | Site name/code/email, department name/code (SITE-01, DEP-01). | Generate the DTO limits from the entity, or add a test that compares them. |
| **Inputs accepted but never stored.** | Department `settings` and `area` (DEP-02), site `facilities`/`notes`/`metadata` (SITE-05), a species' official code on update and its compatible feeds (SPC-01, SPC-08), a supplier's contacts, organisation number, description, fax and certifications (SUP-02, SUP-10, SUP-23). | Remove the field from the API, or add the column. |
| **Numbers without bounds.** Volumes, biomass, capacity and counts accept negative values and fractions. | Systems (SYS-03), departments (DEP-12), sites, equipment specifications (EQ-19); tanks bounded alike for every kind (TNK-11). | `@Min(0)` (and `@IsInt` for counts) on the DTO, `CHECK` on the column, `min` on the input. |
| **Foreign-key behaviour declared one way in the entity and another in the database.** | `ON DELETE CASCADE`/`SET NULL` in the entities, `RESTRICT` in all 62 baseline FKs. | Pick one source of truth (the migration) and generate or test the other against it. |
| **Soft delete and relations do not meet.** Handlers re-implement the consequences per entity, and the sets differ. | Site, department and system delete rules differ and each has gaps (SITE-06, DEP-08, SYS-08, SYS-09). | One delete mechanism that follows the relations (what the prototype's `core/softdelete.py` does). |
| **Lookups that forget `isDeleted`.** | Update/get of a deleted department, site and species (SPC-14); creating a system under a deleted site, department or parent. | Make the soft-delete filter part of the repository, not of each query. |
| **Enum and default drift.** | Department default type: database `production`, form `HATCHERY`, API requires it (DEP-09). | One default, defined once, in the database. |
| **Language mixed inside one screen.** | Delete dialogs are hard-coded Turkish inside an English UI; typo "silindığında"; equipment type labels and descriptions (EQ-17); the species tab (SPC-29). | Put every string in the message catalog. |
| **Two status flags** (`status` and `isActive`) that can disagree, with different readers. | Sites (SITE-10), departments (DEP-07), species: a discontinued species stays selectable for new batches (SPC-15), suppliers: a blacklisted supplier stays offered (SUP-05). | One field, `status`, and a stated rule for which statuses count as usable. |
| **Stored unit fields that no reader honours.** | Species growth figures: harvest weights are read as grams and densities as kg/m³ whatever the unit says (SPC-17). | Put the unit in the field (`harvest_weight_g`), never in a separate field the readers can ignore. |
| **Links by name or code instead of by id.** | Protocols, cleaner-fish details and stock snapshots copy a species' name; water-quality limits are keyed by its code (SPC-26). Purchase orders copy the supplier's name (SUP-19). | A foreign key; copies only where a record must stay frozen (a filed report). |

### Bounds per kind (`LIMITS` in farm/models/tank.py)

The source used one set of bounds for every kind (TNK-11). The prototype bounds each measure per
kind, wide enough for the largest farms in operation and tight enough to stop a typing slip (a lost
decimal separator, metres typed as millimetres). The form shows them in each field's help, and the
database holds the same bounds.

### Questions for the owner

The status machine is ported exactly (TNK-12). These moves are not in the source's table and are not
added; they are common on farms and need a decision:

- **harvesting → active**: a partial harvest leaves fish in the unit.
- **maintenance → active**, **cleaning → active** and **fallow → active**: a unit put straight back
  into use; stocking in the source already does fallow → active outside the table (TNK-14).
- **active → cleaning** and **active → inactive**: cleaning or retiring an active unit that is empty.
- Whether **fallow, maintenance and quarantine** need an empty unit (fallowing means empty): the source
  does not check it, and the prototype does not either until it is decided.
- A cage's volume is a cylinder (or a box) down to the net depth, as in the source; a net with a cone
  at the bottom holds less. A cone depth would make it exact.
