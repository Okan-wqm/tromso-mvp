# Bugs found in the aquaculture platform while porting the farm module

Porting the farm module tab by tab means reading its source closely. This document lists what was
found wrong, so it can be fixed in the platform and so the prototype does not repeat it. It grows
with every tab that is ported.

**Source read:** `aquaculture_platform`, branch `snowball-test`, commit `352aa2a8`
(`apps/farm-service`, `web/modules/farm-module`). Paths below are relative to those two folders.

**How reliable each entry is.** Findings come from reading the source. Those marked **✔** were
re-read by hand at the cited lines; the others are as reported by the analysis of the file and
should be confirmed at the cited place before fixing. Line numbers can drift with the branch.

**Severity:** **High** wrong or lost data, or a behaviour the user cannot work around;
**Medium** wrong in some cases, or a trap for later changes; **Low** inconsistency or polish.

**"In the prototype"** says how it is avoided here: by a database constraint, a shared mechanism
in `core/`, or by not porting the feature (satellite monitoring is deliberately left out).

## Patterns that repeat across tabs

These are the root causes behind many of the single entries below. Fixing them once, where they
live, closes the whole class.

| Pattern | Where it shows | Root-cause fix |
|---|---|---|
| **A cleared field cannot be saved.** The forms send `value \|\| undefined`, and the API reads `undefined` as "no change". | Equipment: every optional field and the parent (EQ-02). Systems: department, parent system, description (SYS-01). Departments: notes (DEP-03). Tanks: system, description, sensor (TNK-16). Species: local name, family, official code, notes and more (SPC-09). Suppliers: every optional field (SUP-07). Feeds: every optional field and the whole analysis (FEED-03). | Send `null` for a cleared optional field, and let the API treat `null` as "clear" and absent as "unchanged". One helper for every form. |
| **Rules that live only in the service code.** The database accepts what the service would refuse. | Name/code uniqueness, one primary contact, department/site match. | Put the rule in the database (unique index with a `WHERE`, check constraint, composite FK) and keep the service check only to give a readable message. |
| **Unique indexes that are not partial** while the services only check live rows. | Sites, departments, systems, species (SPC-12): a deleted record's code can never be reused, and the clash surfaces as a database error. | Make the unique index partial (`WHERE "isDeleted" = false`), or decide that codes are never reused and say so in the message. |
| **Input limits longer than the column.** | Site name/code/email, department name/code (SITE-01, DEP-01). | Generate the DTO limits from the entity, or add a test that compares them. |
| **Inputs accepted but never stored.** | Department `settings` and `area` (DEP-02), site `facilities`/`notes`/`metadata` (SITE-05), a species' official code on update and its compatible feeds (SPC-01, SPC-08), a supplier's contacts, organisation number, description, fax and certifications (SUP-02, SUP-10, SUP-23), a feed's species mappings and its upper fish weight (FEED-01, FEED-02). | Remove the field from the API, or add the column. |
| **Numbers without bounds.** Volumes, biomass, capacity and counts accept negative values and fractions. | Systems (SYS-03), departments (DEP-12), sites, equipment specifications (EQ-19); tanks bounded alike for every kind (TNK-11). | `@Min(0)` (and `@IsInt` for counts) on the DTO, `CHECK` on the column, `min` on the input. |
| **Foreign-key behaviour declared one way in the entity and another in the database.** | `ON DELETE CASCADE`/`SET NULL` in the entities, `RESTRICT` in all 62 baseline FKs. | Pick one source of truth (the migration) and generate or test the other against it. |
| **Soft delete and relations do not meet.** Handlers re-implement the consequences per entity, and the sets differ. | Site, department and system delete rules differ and each has gaps (SITE-06, DEP-08, SYS-08, SYS-09). | One delete mechanism that follows the relations (what the prototype's `core/softdelete.py` does). |
| **Lookups that forget `isDeleted`.** | Update/get of a deleted department, site and species (SPC-14), supplier (SUP-14) and feed (FEED-11); creating a system under a deleted site, department or parent. | Make the soft-delete filter part of the repository, not of each query. |
| **Enum and default drift.** | Department default type: database `production`, form `HATCHERY`, API requires it (DEP-09). | One default, defined once, in the database. |
| **Language mixed inside one screen.** | Delete dialogs are hard-coded Turkish inside an English UI; typo "silindığında"; equipment type labels and descriptions (EQ-17); the species tab (SPC-29). | Put every string in the message catalog. |
| **Two status flags** (`status` and `isActive`) that can disagree, with different readers. | Sites (SITE-10), departments (DEP-07), species: a discontinued species stays selectable for new batches (SPC-15), suppliers: a blacklisted supplier stays offered (SUP-05), feeds: a discontinued feed stays offered (FEED-19). | One field, `status`, and a stated rule for which statuses count as usable. |
| **Stored unit fields that no reader honours.** | Species growth figures: harvest weights are read as grams and densities as kg/m³ whatever the unit says (SPC-17). | Put the unit in the field (`harvest_weight_g`), never in a separate field the readers can ignore. |
| **Links by name or code instead of by id.** | Protocols, cleaner-fish details and stock snapshots copy a species' name; water-quality limits are keyed by its code (SPC-26). Purchase orders copy the supplier's name (SUP-19). | A foreign key; copies only where a record must stay frozen (a filed report). |

### Bounds per kind (`LIMITS` in farm/models/tank.py)

kind, wide enough for the largest farms in operation and tight enough to stop a typing slip (a lost
decimal separator, metres typed as millimetres). The form shows them in each field's help, and the
database holds the same bounds.

### Questions for the owner

The status machine is ported exactly (TNK-12). These moves are not in the source's table and are not
added; they are common on farms and need a decision:

- **harvesting → active**: a partial harvest leaves fish in the unit.
- **maintenance → active**, **cleaning → active** and **fallow → active**: a unit put straight back
  into use; stocking in the source already does fallow → active outside the table (TNK-14).
- **active → cleaning** and **active → inactive**: cleaning or retiring an active unit that is empty.
- Whether **fallow, maintenance and quarantine** need an empty unit: with the stock ported, the prototype
  follows the stock design (STK-07): active and harvesting need fish; preparing, fallow, cleaning and inactive
  need none; maintenance and quarantine can be either. The owner can still change it.
- A cage's volume is a cylinder (or a box) down to the net depth, as in the source; a net with a cone
  at the bottom holds less. A cone depth would make it exact.

## Stock and production units

The source's Tanks page (`/sites/tanks`) shows every unit with its fish, and its drawer holds the
operations on them: stocking, mortality, cull, transfer, grading, a weigh-in. Behind it the count of a
unit lives in six places and its biomass in seven, kept beside each other by hand; four append-only
tables are written next to them and read by nothing. The prototype keeps one ledger and computes
everything from it (Operations › Production units; `farm/models/stock.py`, `farm/stock/`).

Backend paths are relative to `apps/farm-service/src`, frontend paths to `web/modules/farm-module/src`
(`TanksPage.tsx`, `TankTable.tsx` and `TankDetailDrawer.tsx` under `pages/tanks/`, the dialogs under
`pages/production/components/`), `en.ts`/`tr.ts` to `web/shared-ui/src/i18n/locales/`. The last column
maps each entry to the two analysis reports it merges: **D** (data model and backend, its STK numbers)
and **F** (the page and its dialogs, its bug numbers). Stocking, mortality, cull, weighing, transfer and
split, grading and harvest are ported, each voidable; count adjustments have their line kind and checks
but no dialog yet. STK-26 and STK-50 of report D are merged into STK-07 and STK-06; STK-56 onwards are the page's own.

## Feeding records

The source records feed per batch: a meal pour books it on the unit's "primary" batch, a manual record on
whatever batch the client names, and the web dialog has no unit input at all, so manual records have no
unit. Every record then adds `fed kg / expected FCR` to the stock's biomass, so the unit FCR meets its
target by construction and tomorrow's ration grows whether the fish did or not. There is no void; three
FCR formulas disagree; last fed is never written; recording fails when the feed store is empty; records
older than 800 days are deleted while FCR sums them. The prototype records feed per unit and day, derives
the batches fed from the stock ledger, and reads FCR, last fed and the feed rate from the records and the
ledger without storing anything (Operations › Feeding records; `farm/models/feeding.py`, `farm/feeding/`).

### Plausible ranges (`farm/water/parameters.py`)

The ranges catch a typing slip (a lost decimal separator, a value typed into the wrong field); they are
not limits, which are the owner's per species. Each is a database check and the form's bound; the
precision is the column's. Owner decision 4 confirms them; the reasons:

| Parameter | Range | Decimals | Why |
|---|---|---|---|
| Temperature (°C) | −3 … 40 | 1 | Sea water freezes at about −1.9 °C, supercooled water and probes in ice slurry read a little lower; warm-water species (tilapia, catfish) are farmed up to about 35 °C. 300 °C (WQ-07) is refused. |
| Dissolved oxygen (mg/L O₂) | 0 … 50 | 2 | Air saturation is 14.6 mg/L at 0 °C; inflow from oxygen cones and LHOs runs at 200–300 % of air saturation, about 30–45 mg/L in cold water. A negative value is a probe fault. |
| Oxygen saturation (%) | 0 … 400 | 1 | The same oxygenated inflow in %, with headroom; one decimal, as optical meters show it (the analysis proposed none). |
| pH (NBS) | 2 … 12 | 2 | No farmed fish lives below 4 or above 10; the wider range still lets a liming mistake or an acid spill be recorded as it was read. pH 25 is refused. |
| Alkalinity (mg/L CaCO₃) | 0 … 1000 | 0 | Soft fresh water is near 0, sea water about 115, a limed RAS 150–300; 1000 is far above any dosing. |
| Carbon dioxide (mg/L) | 0 … 200 | 1 | RAS run at 10–40 mg/L; a closed transport tank or a failed degasser can pass 100. |
| TAN (mg/L N) | 0 … 100 | 3 | RAS grow-out sits at 0.5–5, a crash or a transport water at 20–50; three decimals for laboratory results to 0.001 (the analysis proposed two). |
| Nitrite (mg/L N) | 0 … 100 | 3 | Freshwater salmonids are harmed above about 0.1, marine RAS run at 1–5, a nitrifying start-up can pass 20. |
| Nitrate (mg/L N) | 0 … 1000 | 1 | Low-exchange RAS accumulate 100–400 mg/L N, systems without denitrification more. |
| TGP (%) | 50 … 200 | 1 | Saturometers read 70–130 % in practice; below 50 or above 200 % is not water a fish could be in. |
| Salinity (‰) | 0 … 50 | 1 | Fresh water 0, the ocean 35, hypersaline ponds and brine dosing up to about 45. |
| Turbidity (NTU) | 0 … 4000 | 1 | Clear RAS water is below 2; flooded earthen ponds reach hundreds, and turbidimeters top out at 1000–4000. |

### Starting points for the owner (not seeded)

For Atlantic salmon, from commonly cited guidance, all **INFERRED** and to be confirmed by a vet before
they are entered as limits: oxygen saturation warning below 80 %, critical below 60 %; CO₂ warning above
10, critical above 15 mg/L; TGP warning above 101 %, critical above 103 %; NH₃-N warning above 0.01,
critical above 0.02 mg/L; nitrite-N in fresh water warning above 0.1 mg/L.

### Owner decisions taken for the MVP (they can be changed)

1. **Empty units**: their samples are recorded and shown; a value is judged only against the limits of
   the species present, so an empty unit shows its values with "no limit".
2. **Status of old samples**: computed on read against the current limits; the limits of the time are not
   kept (that needs limit history, left for later). The page and the README say so.
3. **Units of record**: nitrogen "as N" (TAN, nitrite-N, nitrate-N), labelled so, with the kit
   conversions in the help.
4. **Plausible ranges**: the table above.
